# آموزش پله‌به‌پلهٔ اضافه‌کردن فونت در VoiceWeb

[فهرست مستندات](./README.fa.md) · [مرجع تنظیمات فونت](./FONTS.fa.md) · [شرح توابع لودر](./inc/fonts.fa.md)

هدف این آموزش این است که بدانی فایل فونت را کجا بگذاری، چطور آن را با PHP
ثبت کنی، هر خط چه کاری می‌کند، چطور فونت به متن می‌رسد و از کجا بفهمی واقعاً
درست اجرا شده است. مثال اصلی، جایگزینی فونت فارسی با `Yekan Bakh VF` است؛
فایل آن همین حالا در پروژه وجود دارد. بعد از آن، افزودن فایل جدید، چند وزن
ثابت، زبان جدید و روش CSS جدا را تمرین می‌کنیم.

**این سند آموزشی است؛ نوشتن این راهنما تنظیم فعال سایت را تغییر نداده است.**
نمونه‌های جایگزین را هم‌زمان کپی نکن؛ هر سناریو را جداگانه اجرا کن.

## ۱. اول سه مفهوم را از هم جدا کن

| مفهوم | مثال | وظیفه |
|---|---|---|
| فایل فونت | `YekanBakh-VF.ttf` | دادهٔ شکل حروف و وزن‌ها |
| تعریف فونت | `@font-face` | معرفی فایل به مرورگر با یک نام و مشخصات |
| انتخاب فونت | `font-family` | تعیین فونتی که یک عنصر باید استفاده کند |

صرفاً کپی‌کردن فایل در `assets/fonts`، آن را ثبت یا فعال نمی‌کند. صرفاً نوشتن
نام یک فونت در `font-family` هم فایل آن را دانلود نمی‌کند؛ باید قبلاً با
`@font-face` معرفی شده باشد یا روی سیستم کاربر موجود باشد.

در این قالب، PHP از تنظیم تو، `@font-face` را می‌سازد و نام انتخاب‌شده را در
متغیر `--cn-font-family` قرار می‌دهد. بنابراین برای روش اصلی به تعریف دستی
فونت در CSS نیاز نداری. ساختار عمومی این قاعده در
[مرجع MDN برای @font-face](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face)
توضیح داده شده است.

## ۲. نقشهٔ فایل‌های همین پروژه

همهٔ مسیرهای نسبی این آموزش از ریشهٔ وردپرس، یعنی مسیر زیر، شروع می‌شوند:

```text
C:\Users\123\Local Sites\woo-theme-1405\app\public
```

| فایل | نقش در این سناریو |
|---|---|
| [config/fonts.php](../config/fonts.php) | تنظیم پیش‌فرض فونت هر زبان در والد |
| [inc/fonts.php](../inc/fonts.php) | خواندن تنظیم، تشخیص زبان، ساخت CSS و preload |
| [inc/assets.php](../inc/assets.php) | پیدا کردن فایل در چایلد/والد و اجرای لودر فونت |
| [functions.php والد](../functions.php) | بارگذاری فایل‌های PHP بالا |
| [functions.php چایلد](../../voiceweb-child/functions.php) | محل ثبت تغییر اختصاصی پروژه با filter |
| [global.scss چایلد](../../voiceweb-child/assets/scss/global.scss) | محل استایل سراسری، اگر تغییر استایل هم لازم باشد |
| [توکن‌های Sass والد](../assets/scss/abstracts/_tokens.scss) | مقدار `$font-family` برابر `var(--cn-font-family)` |

تنظیم پایهٔ فعلی فارسی، خانوادهٔ `Dana VF` با فایل `assets/fonts/DanaVF.ttf`
و مقدار تنظیمی `weight => '1 1000'` است. انگلیسی از
`Arial, Helvetica, sans-serif` استفاده می‌کند. فایل
`assets/css/fonts.css` شامل وزن‌های ثابت Dana است، اما تنظیم فعلی فارسی به آن
ارجاع نمی‌دهد.

**جزئیات فایل واقعی:** جدول `fvar` فایل فعلی `DanaVF.ttf` محور `wght` با بازهٔ
`10 990` و محور `KASH` با بازهٔ `0 100` دارد؛ پس بازهٔ اعلام‌شده در config
فعلی دقیقاً برابر بازهٔ فایل نیست. در مثال این سند از `YekanBakh-VF.ttf`
استفاده می‌کنیم که محور `wght` آن واقعاً `1 1000` است. اگر بعداً تنظیم Dana
را اصلاح کردی، بازهٔ وزن را مطابق فایل همان نسخه وارد کن. لودر فعلی جدول‌های
داخل فونت را نمی‌خواند و این اختلاف را خودش تشخیص نمی‌دهد.

## ۳. پیش‌نیاز: چایلد قالب باید فعال باشد

در «نمایش ← پوسته‌ها» بررسی کن قالب فعال `voiceweb-child` باشد. وجود پوشهٔ
چایلد به‌تنهایی کافی نیست. این آموزش تغییرات پروژه را در چایلد قرار می‌دهد.

فایل `functions.php` چایلد پیش از فایل والد بارگذاری می‌شود و هر دو اجرا
می‌شوند. پس filter را می‌توان همان ابتدا در چایلد ثبت کرد تا وقتی والد
تنظیمات فونت را می‌خواند، آن را اجرا کند؛ در این مرحله نباید خود تابع
`cn_font_config()` را مستقیم فراخوانی کنی، چون هنوز ممکن است تعریف نشده باشد.
این ترتیب در [راهنمای رسمی چایلد وردپرس](https://developer.wordpress.org/themes/advanced-topics/child-themes/)
نیز توضیح داده شده است.

فایل `voiceweb-child/config/fonts.php` با کپی‌کردن خودکار جای config والد را
نمی‌گیرد: تابع `cn_font_config()` صریحاً از `get_template_directory()` استفاده
می‌کند. نقطهٔ تغییر تنظیم برای چایلد، filter با نام `cn/font-config` است.

## ۴. پلهٔ اول: فایل فونت را آماده کن

برای تمرین قابل اجرا از فایل موجود زیر استفاده کن:

```text
wp-content/themes/voiceweb/assets/fonts/YekanBakh-VF.ttf
```

پوشهٔ `assets/fonts` را در چایلد بساز و **یک کپی** از فایل در این محل بگذار:

```text
wp-content/themes/voiceweb-child/assets/fonts/YekanBakh-VF.ttf
```

این کار را می‌توانی در File Explorer انجام بدهی. اگر فایل مقصد از قبل وجود
دارد، اول بررسی کن همان نسخه‌ای باشد که قصد استفاده از آن را داری.

مقداری که بعداً در `path` می‌نویسیم این است:

```text
assets/fonts/YekanBakh-VF.ttf
```

در `path` نه مسیر ویندوز بنویس، نه آدرس سایت، نه `wp-content/themes` و نه نام
پوشهٔ چایلد. این مقدار نسبت به ریشهٔ قالب است و با `/` نوشته می‌شود.

لودر با `cn_asset()` ابتدا فایل هم‌مسیر در چایلد فعال و سپس فایل والد را پیدا
می‌کند. بنابراین این مثال حتی بدون کپی نیز فایل فعلی والد را پیدا می‌کند؛
کپی‌کردن، تمرین نگهداری فایل فونت در چایلد است. این fallback برای **خود فایل
asset** است و با انتخاب زبان یا فونت جایگزین مرورگر فرق دارد.

## ۵. پلهٔ دوم: تنظیم کامل را در چایلد ثبت کن

فایل زیر را باز کن:

```text
wp-content/themes/voiceweb-child/functions.php
```

کد زیر را در انتهای بخش PHP، بعد از کدهای موجود و بیرون از هر تابع دیگری
اضافه کن. فایل فعلی با `<?php` شروع شده است؛ آن را دوباره ننویس. کدهای
قبلی را پاک نکن. اگر قبلاً filter فونت فارسی اضافه کرده‌ای، همان را ویرایش
کن تا چند callback مختلف تنظیم `fa` را روی هم بازنویسی نکنند.

```php
/**
 * Select Yekan Bakh Variable for Persian front-end pages.
 */
add_filter(
	'cn/font-config',
	function ( $fonts ) {
		$fonts['fa'] = array(
			'family'      => '"Yekan Bakh VF", Tahoma, sans-serif',
			'stylesheets' => array(),
			'font_faces'  => array(
				array(
					'family'  => 'Yekan Bakh VF',
					'path'    => 'assets/fonts/YekanBakh-VF.ttf',
					'format'  => 'ttf',
					'weight'  => '1 1000',
					'style'   => 'normal',
					'display' => 'swap',
					'preload' => true,
				),
			),
			'preload'     => array(),
		);

		return $fonts;
	}
);
```

### توضیح خط‌به‌خطِ ثبت filter

| عبارت | معنی دقیق |
|---|---|
| `add_filter(...)` | ثبت تابعی که بعداً تنظیمات فونت از آن عبور می‌کنند |
| `'cn/font-config'` | نام نقطهٔ توسعهٔ تعریف‌شده در قالب؛ باید دقیقاً همین باشد |
| `function ( $fonts )` | تابع بی‌نامی که آرایهٔ فعلی همهٔ زبان‌ها را می‌گیرد؛ به `$this` وابسته نیست |
| `$fonts['fa'] = array(...)` | جایگزین‌کردن کل تنظیم فارسی؛ تنظیم انگلیسی و default حفظ می‌شوند |
| `=>` | اتصال نام یک کلید به مقدار آن در آرایهٔ PHP |
| `array()` | آرایهٔ خالی؛ در اینجا یعنی آن نوع منبعی نداریم |
| `return $fonts;` | تحویل نقشهٔ اصلاح‌شده به لودر؛ حذف این خط خروجی صحیح filter را از بین می‌برد |

### چرا دو بار `family` داریم؟

مقدار بیرونی، فهرست اولویت فونت‌ها برای متن است:

```php
'family' => '"Yekan Bakh VF", Tahoma, sans-serif',
```

مرورگر ابتدا خانوادهٔ اول را در نظر می‌گیرد و برای نویسه‌هایی که آن فونت
قابل نمایش نیست یا فونت قابل استفاده نیست، از گزینه‌های بعدی کمک می‌گیرد.
نوشتن `Tahoma` باعث دانلود فایل جدید توسط این قالب نمی‌شود.

مقدار داخلی فقط نام خانواده‌ای است که این فایل با آن در CSS ثبت می‌شود:

```php
'family' => 'Yekan Bakh VF',
```

نام داخلی نباید شامل فهرست `Tahoma, sans-serif` باشد. نام اول در مقدار بیرونی
باید با این نام هماهنگ باشد. این نام، نام ثبت‌شدهٔ CSS است و الزاماً نام فایل
نیست؛ می‌توان alias دیگری انتخاب کرد، به شرط هماهنگی تعریف و مصرف.

در مقدار بیرونی، کوتیشن تکی رشتهٔ PHP را می‌سازد و کوتیشن دوتاییِ داخل آن به
CSS می‌رسد. در مقدار داخلی کوتیشن اضافی دور نام لازم نیست؛ لودر آن را هنگام
تولید CSS اضافه می‌کند.

### مشخصات هر فایل چه می‌گویند؟

| کلید | مقدار مثال | توضیح |
|---|---|---|
| `path` | `assets/fonts/YekanBakh-VF.ttf` | محل فایل نسبت به قالب |
| `format` | `ttf` | لودر آن را در CSS به `truetype` تبدیل می‌کند |
| `weight` | `1 1000` | یک فایل متغیر با این بازهٔ وزن؛ دو عدد با فاصله |
| `style` | `normal` | این تعریف مربوط به حالت عادی است |
| `display` | `swap` | ابتدا امکان نمایش با فونت جایگزین و بعد تعویض با فونت آماده‌شده |
| `preload` | `true` | درخواست زودتر همین فایل در head |

`weight` مشخصات فایل است، نه وزن همهٔ متن‌های سایت. وزن عنوان و پاراگراف را
همچنان `font-weight` عناصر تعیین می‌کند. نوشتن بازه برای یک فایل ثابت، آن
را به فونت متغیر تبدیل نمی‌کند. همین‌طور تغییر پسوند `.ttf` به `.woff2`
تبدیل فرمت نیست؛ فرمت اعلام‌شده باید با فایل واقعی منطبق باشد.

کلید اختیاری `stretch` هم برای درصد یا بازهٔ کشیدگی وجود دارد، اما در مثال
ما لازم نیست. فقط ویژگی و بازه‌ای را اعلام کن که فایل واقعاً پشتیبانی می‌کند.

### چرا `stylesheets` و `preload` بیرونی خالی هستند؟

`stylesheets` خالی است چون تعریف‌ها از `font_faces` تولید می‌شوند. اگر CSS
قدیمی هم باقی بماند، ممکن است تعریف‌های اضافی یا متعارض وارد صفحه شوند.

`preload` داخلی یک مقدار بولی برای همان face است. `preload` بیرونی فهرست
مسیرهای اضافی است. چون فایل اصلی با مقدار داخلی معرفی شده، لازم نیست دوباره
در فهرست بیرونی قرار بگیرد. لودر مسیرهای دقیقاً یکسان را تکراری حساب می‌کند،
اما بهتر است تنظیم از ابتدا روشن و بدون تکرار باشد. تمام وزن‌های یک خانواده
را صرفاً به دلیل وجود فایلشان preload نکن.

## ۶. پلهٔ سوم: بفهم بعد از ذخیره چه کدی اجرا می‌شود

این مسیر مربوط به کد فعلی قالب است:

```text
functions.php چایلد: ثبت cn/font-config
    ↓
functions.php والد: require کردن inc/fonts.php و inc/assets.php
    ↓
wp_enqueue_scripts → cn_enqueue_language_fonts()
    ↓
cn_font_settings() → cn_font_config() → config والد + filter چایلد
    ↓
cn_font_language() → انتخاب تنظیم زبان
    ↓
cn_font_faces_css() → cn_asset(path) → ساخت @font-face
    ↓
cn-fonts → CSS داخل صفحه + --cn-font-family

wp_head با اولویت 1 → تنظیم همان زبان → چاپ preload
```

`cn_font_config()` تنظیم را فقط بار اول در همان درخواست PHP می‌خواند و در
متغیر `static` نگه می‌دارد. این کش دائمی نیست؛ درخواست تازه دوباره config را
می‌خواند. filter باید پیش از اولین خواندن ثبت شده باشد؛ قرار دادن آن در
فوتر یا یک callback دیرهنگام مناسب نیست.

تابع `cn_asset()` وجود فایل را بررسی می‌کند. اگر فایل پیدا نشود، سازندهٔ
`@font-face` آن تعریف را کنار می‌گذارد. بنابراین **نبودن خطای 404 به معنی
درست‌بودن مسیر نیست**؛ ممکن است اصلاً URL فونت در خروجی ساخته نشده باشد.

### خروجی مورد انتظار در HTML

در صفحهٔ فارسی، نمونهٔ خواناشدهٔ خروجی چنین است. `example.test` فقط جای‌نگهدار
دامنه است؛ آدرس واقعی را خود وردپرس می‌سازد. این کد را دستی در header نگذار:

```html
<link rel="preload"
      href="https://example.test/wp-content/themes/voiceweb-child/assets/fonts/YekanBakh-VF.ttf"
      as="font" type="font/ttf" crossorigin>

<style id="cn-fonts-inline-css">
@font-face {
    font-family: "Yekan Bakh VF";
    src: url("https://example.test/wp-content/themes/voiceweb-child/assets/fonts/YekanBakh-VF.ttf") format("truetype");
    font-weight: 1 1000;
    font-style: normal;
    font-display: swap;
}
:root {
    --cn-font-family: "Yekan Bakh VF", Tahoma, sans-serif;
}
body, button, input, select, textarea {
    font-family: var(--cn-font-family);
}
</style>
```

`cn-fonts` یک handle وردپرس بدون فایل CSS خارجی است؛ پس انتظار درخواست
`cn-fonts.css` در Network نداشته باش. کد آن در HTML قرار دارد. اگر فایل از
والد پیدا شده باشد، URL شامل `voiceweb` خواهد بود.

## ۷. پلهٔ چهارم: استفاده در متن و کنترل‌های رابط

برای عوض‌شدن فونت عمومی با مثال بالا نیازی به تغییر Sass نیست. قالب خودش
`body` و `button` و `input` و `select` و `textarea` را تنظیم می‌کند؛ بسیاری
از عناصر دیگر فونت را از والد به ارث می‌برند.

اگر یک کامپوننت قانون فونت اختصاصی دارد، همان قانون را بررسی کن. نمونهٔ
اختیاری زیر را می‌توانی به انتهای `global.scss` چایلد اضافه کنی:

```scss
.font-demo {
    font-family: var(--cn-font-family);
    line-height: 1.9;
}

.font-demo__regular { font-weight: 400; }
.font-demo__medium  { font-weight: 500; }
.font-demo__bold    { font-weight: 700; }
.font-demo__heavy   { font-weight: 900; }
```

نام کلاس‌ها برای تمرین است؛ تا markup متناظر نداشته باشی اثری نمی‌بینی:

```html
<div class="font-demo" lang="fa" dir="rtl">
    <p class="font-demo__regular">وزن ۴۰۰؛ سفر به شیراز، قیمت ۱۲۳۴۵۶۷۸۹۰</p>
    <p class="font-demo__medium">وزن ۵۰۰؛ سفر به شیراز، قیمت ۱۲۳۴۵۶۷۸۹۰</p>
    <p class="font-demo__bold">وزن ۷۰۰؛ سفر به شیراز، قیمت ۱۲۳۴۵۶۷۸۹۰</p>
    <p class="font-demo__heavy">وزن ۹۰۰؛ سفر به شیراز، قیمت ۱۲۳۴۵۶۷۸۹۰</p>
</div>
```

این markup را در برگهٔ آزمایشیِ فارسی، در بخشی که HTML سفارشی می‌پذیرد، قرار
بده. صرف `lang="fa"` روی یک div، انتخاب زبان PHP قالب را عوض نمی‌کند؛ خود
درخواست باید صفحهٔ فارسی باشد.

اگر SCSS را تغییر دادی، خروجی `assets/css/global.css` چایلد را با تنظیم
موجود **Watch Sass** بساز؛ مرورگر SCSS نمی‌خواند. فایل فعلی `global.scss`
چایلد، استایل والد را با `@use` وارد می‌کند؛ محتوای موجود را با نمونهٔ بالا
جایگزین نکن. جزئیات کامپایل در [راهنمای Sass](./JS-SASS-LOADING.fa.md) است.

قانون عمومی `* { font-family: ... !important; }` ننویس؛ آیکن‌هایی که خانوادهٔ
فونت مخصوص دارند هم تحت تأثیر قرار می‌گیرند. برای مشکل یک کامپوننت، selector
همان کامپوننت را اصلاح کن.

## ۸. پلهٔ پنجم: بررسی در مرورگر

### ۸.۱. بررسی PHP قبل از بازکردن صفحه

در ترمینال از ریشهٔ وردپرس اجرا کن؛ PHP باید در دسترس ترمینال باشد:

```powershell
php -l wp-content/themes/voiceweb-child/functions.php
```

انتظار داری پیام `No syntax errors detected` ببینی. این دستور فقط صحت نحوی
PHP را بررسی می‌کند، نه موجودبودن فایل فونت یا نتیجهٔ نمایش مرورگر را.

### ۸.۲. بررسی منبع صفحه و دانلود

1. صفحهٔ فارسی را باز کن؛ در DevTools بخش Network، گزینهٔ `Disable cache`
   را فعال کن و در حالی که DevTools باز است صفحه را reload کن.
2. در منبع HTML، `cn-fonts-inline-css` را جست‌وجو کن. نام `Yekan Bakh VF` و
   مسیر فایل باید داخل آن باشند.
3. در Network نوع `Font` را بررسی کن. در این سناریو، با فایل موجود و preload
   فعال، انتظار درخواست `YekanBakh-VF.ttf` داری. پاسخ باید فایل فونت باشد،
   نه یک صفحهٔ HTML با کد پاسخ ظاهراً موفق.
4. مقدار `Content-Type` فونت TTF را بررسی کن؛ مقدار مورد انتظار `font/ttf`
   است. خطای decode، MIME یا CORS را نیز در Console بررسی کن.
5. اگر از چایلد کپی گرفته‌ای، URL درخواست باید به فایل چایلد اشاره کند.

### ۸.۳. فرق «فونت خواسته‌شده» و «فونت واقعاً نمایش‌داده‌شده»

در Console می‌توانی مقدار درخواستی را ببینی:

```javascript
getComputedStyle(document.body).fontFamily
```

برای دیدن متغیر قالب:

```javascript
getComputedStyle(document.documentElement)
    .getPropertyValue('--cn-font-family')
    .trim()
```

وجود نام صحیح در این خروجی‌ها، دانلود یا استفادهٔ واقعی از فونت را ثابت
نمی‌کند. متن فارسی را با Inspect انتخاب کن و در بخش Computed، قسمت
`Rendered Fonts` را ببین. نام داخلی گزارش‌شدهٔ فونت ممکن است با alias انتخابی
در CSS متفاوت باشد؛ منبع فایل و حروف رندرشده را هم بررسی کن. برای متن ترکیبی
ممکن است بیش از یک فونت استفاده شود.

برای درخواست و بررسی face متناظر هم می‌توانی اجرا کنی:

```javascript
document.fonts.load('700 16px "Yekan Bakh VF"', 'سلام ۱۲۳').then((faces) => {
    console.table(faces.map((face) => ({
        family: face.family,
        weight: face.weight,
        status: face.status
    })));
}).catch(console.error);
```

آرایهٔ خالی یعنی face متناظری پیدا نشده؛ نتیجهٔ دارای `status: "loaded"`
موفقیت بارگذاری face را نشان می‌دهد. این بررسی به‌تنهایی تضمین پوشش تک‌تک
نویسه‌ها یا استفادهٔ عنصر از فونت نیست؛ نتیجه را با `Rendered Fonts` همان
عنصر کنار هم بررسی کن. رفتار API در
[مرجع FontFaceSet.load](https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/load)
آمده است.

### ۸.۴. آزمون زبان و وزن

چهار وزن نمونه را کنار هم ببین. سپس صفحهٔ انگلیسی را جدا باز کن. با تنظیمات
این مثال، CSS تولیدشدهٔ لودر برای انگلیسی نباید face فارسی یا preload آن را
داشته باشد. اگر در صفحهٔ انگلیسی درخواست فونت فارسی دیدی، Initiator آن را
بررسی کن؛ ممکن است افزونه یا CSS دیگری مستقلاً فونت را بارگذاری کند.

این لودر مخصوص فرانت‌اند قالب است؛ تغییرنکردن فونت پیشخوان یا محیط ویرایشگر
با این تنظیم، نشانهٔ خرابی سناریو نیست.

## ۹. سناریوی بعدی: فایل فونت متغیر کاملاً جدید

فرض کن فایل واقعی جدیدی با نام `MyPersian-VF.woff2` داری و مستندات یا مشخصات
همان فایل می‌گویند بازهٔ وزن آن `100 900` است. این نام و بازه **نمونه** هستند؛
چنین فایلی همراه این آموزش اضافه نشده است.

فایل را در این محل بگذار:

```text
wp-content/themes/voiceweb-child/assets/fonts/my-persian/MyPersian-VF.woff2
```

در همان callback پلهٔ دوم، خانوادهٔ بیرونی را به
`'"My Persian", Tahoma, sans-serif'` تغییر بده و **کل مقدار** `font_faces`
را با این مقدار جایگزین کن:

```php
'font_faces' => array(
	array(
		'family'  => 'My Persian',
		'path'    => 'assets/fonts/my-persian/MyPersian-VF.woff2',
		'format'  => 'woff2',
		'weight'  => '100 900',
		'style'   => 'normal',
		'display' => 'swap',
		'preload' => true,
	),
),
```

این قطعه، عضو آرایهٔ تنظیم فارسی است و به‌تنهایی یک برنامهٔ PHP کامل نیست.
مقادیر `stylesheets` و `preload` بیرونی همچنان خالی می‌مانند. سپس مراحل
اعتبارسنجی و مرورگر را با نام جدید تکرار کن.

## ۱۰. سناریوی وزن‌های ثابت: Regular و Bold

فرض کن به‌جای یک فایل متغیر، دو فایل واقعی داری:

```text
voiceweb-child/assets/fonts/my-persian/MyPersian-Regular.woff2
voiceweb-child/assets/fonts/my-persian/MyPersian-Bold.woff2
```

در این حالت `family` بیرونی همان `'"My Persian", Tahoma, sans-serif'`
می‌ماند، اما `font_faces` به شکل زیر جایگزین می‌شود:

```php
'font_faces' => array(
	array(
		'family'  => 'My Persian',
		'path'    => 'assets/fonts/my-persian/MyPersian-Regular.woff2',
		'format'  => 'woff2',
		'weight'  => '400',
		'style'   => 'normal',
		'display' => 'swap',
		'preload' => true,
	),
	array(
		'family'  => 'My Persian',
		'path'    => 'assets/fonts/my-persian/MyPersian-Bold.woff2',
		'format'  => 'woff2',
		'weight'  => '700',
		'style'   => 'normal',
		'display' => 'swap',
		'preload' => false,
	),
),
```

هر دو عضو یک خانواده دارند، چون تفاوتشان وزن است. مرورگر با درخواست
`font-weight: 700` می‌تواند face مخصوص Bold را انتخاب کند. برای وزن `500`
در این مثال فایل مستقل ثبت نشده؛ انتظار طراحی واقعی Medium نداشته باش.

اگر Italic واقعی هم داری، عضو دیگری با نام خانوادهٔ یکسان، مسیر فایل Italic،
وزن درست و `style => 'italic'` اضافه کن. صرف نوشتن `italic` فایل عادی را به
نسخهٔ طراحی‌شدهٔ Italic تبدیل نمی‌کند.

برای تمرین با فایل‌های موجود پروژه نیز می‌توانی به‌جای فایل‌های فرضی بالا از
`assets/fonts/dana/DanaFaNum-Regular.woff2` و
`assets/fonts/dana/DanaFaNum-Bold.woff2` والد استفاده کنی؛ خانوادهٔ هر دو و
خانوادهٔ بیرونی را هماهنگ، مثلاً `Dana`، قرار بده.

## ۱۱. سناریوی CSS آمادهٔ فونت

اگر فایل CSS آماده داری یا به قابلیت‌هایی مثل چند `src` برای یک face یا
`unicode-range` نیاز داری، می‌توانی از `stylesheets` استفاده کنی. schema
فعلی `font_faces` این دو قابلیت را تولید نمی‌کند.

**نکتهٔ مخصوص VoiceWeb:** لودر کامپوننت‌ها فایل‌های مستقیم
`assets/css/*.css` را به‌طور خودکار پیدا می‌کند؛ نام دقیق `fonts.css` مستثنا
است، اما نامی مثل `fonts-fa.css` مستثنا نیست. بنابراین برای CSS اختصاصی زبان
از یک زیرپوشه استفاده کن تا فقط لودر فونت آن را enqueue کند:

```text
voiceweb-child/assets/css/fonts/fa.css
voiceweb-child/assets/fonts/my-persian/MyPersian-Regular.woff2
```

محتوای فایل `fa.css` برای این نمونه:

```css
@font-face {
    font-family: "My Persian";
    src: url("../../fonts/my-persian/MyPersian-Regular.woff2") format("woff2");
    font-weight: 400;
    font-style: normal;
    font-display: swap;
}
```

آدرس داخل CSS نسبت به **خود فایل CSS** محاسبه می‌شود. از `assets/css/fonts/`
دو بار بالا می‌رویم تا به `assets/` برسیم و سپس وارد `fonts/` می‌شویم.
این قاعده با `path` در تنظیم PHP متفاوت است. همچنین URL نسبی CSS، resolver
PHP را صدا نمی‌زند؛ اگر CSS در چایلد است، فایل هدف این URL هم باید آنجا موجود
باشد یا URL مناسب دیگری بنویسی.

این بار در همان callback، کل تنظیم `fa` چنین می‌شود:

```php
$fonts['fa'] = array(
	'family'      => '"My Persian", Tahoma, sans-serif',
	'stylesheets' => array( 'assets/css/fonts/fa.css' ),
	'font_faces'  => array(),
	'preload'     => array(
		'assets/fonts/my-persian/MyPersian-Regular.woff2',
	),
);
```

`font_faces` خالی است چون CSS تعریف را دارد؛ مسیر preload همچنان نسبت به
ریشهٔ قالب است. فایل CSS فقط تعریف فونت داشته باشد؛ انتخاب خانوادهٔ `body`
را همان سیستم مرکزی انجام می‌دهد. در HTML انتظار stylesheet با handle
`cn-font-source-0` و CSS inline با handle `cn-fonts` را داری.

## ۱۲. زبان جدید و اولویت locale

تشخیص زبان با `wpml_current_language` شروع می‌شود. اگر مقدار خالی یا `all`
باشد، لودر سراغ locale وردپرس می‌رود. سپس حروف کوچک می‌شوند و `_` به `-`
تبدیل می‌شود؛ مثلاً `fa_IR` به `fa-ir` می‌رسد.

انتخاب تنظیم برای ورودی `fa-ir` این ترتیب را دارد:

```text
fa-ir موجود است؟ → همان entry
وگرنه fa موجود است؟ → entry فارسی
وگرنه → default
```

اگر WPML مقدار `fa` برگرداند، صرف داشتن entry با نام `fa_IR` باعث انتخاب آن
نمی‌شود؛ ورودی واقعی لودر در آن درخواست `fa` است.

نکتهٔ merge: تنظیم انتخاب‌شده با `default` ادغام می‌شود، نه به‌صورت لایه‌ای
با تنظیم زبان عمومی. یعنی اگر `fa-ir` موجود ولی ناقص باشد، کلیدهای جاافتاده
از `default` می‌آیند، نه از `fa`. برای جایگزینی کامل یک زبان، چهار کلید
اصلی را صریح بنویس.

برای افزودن عربی، می‌توانی **داخل همان callback و قبل از `return $fonts;`**
این نمونه را اضافه کنی؛ مسیر زیر فرضی است و فایل واقعی آن باید موجود باشد:

```php
$fonts['ar'] = array(
	'family'      => '"Arabic UI", Tahoma, sans-serif',
	'stylesheets' => array(),
	'font_faces'  => array(
		array(
			'family'  => 'Arabic UI',
			'path'    => 'assets/fonts/arabic/ArabicUI-Regular.woff2',
			'format'  => 'woff2',
			'weight'  => '400',
			'style'   => 'normal',
			'display' => 'swap',
			'preload' => true,
		),
	),
	'preload'     => array(),
);
```

افزودن کلید `ar` زبان جدیدی در WPML ایجاد نمی‌کند؛ فقط مشخص می‌کند اگر درخواست
عربی شد، چه فونتی انتخاب شود. برای انگلیسی نیز ساختار مشابه با کلید `en`
است. اگر فقط فونت سیستمی انگلیسی را عوض می‌کنی، تغییر همین یک مقدار کافی است:

```php
$fonts['en']['family'] = '"Trebuchet MS", Arial, sans-serif';
```

فونت فارسی، جهت RTL و تبدیل رقم‌ها سه موضوع جدا هستند. این تنظیم فونت متن
`123` را از نظر محتوای رشته به `۱۲۳` تبدیل نمی‌کند؛ ظاهر رقم‌ها به نسخهٔ فونت
و محتوای واقعی هم وابسته است. تبدیل محتوای عدد در پروژه مسیر دیگری دارد.

## ۱۳. عیب‌یابی به ترتیب نشانه

| نشانه | بررسی و اقدام |
|---|---|
| بعد از افزودن کد خطای PHP می‌بینی | خروجی `php -l`، ویرگول‌ها، پرانتزها، محل قرارگیری callback و `<?php` تکراری را بررسی کن |
| نام جدید در inline CSS نیست | فعال‌بودن چایلد، زبان درخواست، ثبت زودهنگام filter، `return $fonts` و filterهای بعدی را بررسی کن |
| نام در stack هست ولی `@font-face` نیست | فایل ناموجود یا family نامعتبر ممکن است face را حذف کرده باشد؛ path و بزرگی/کوچکی حروف نام فایل را بررسی کن |
| درخواست فونت 404 است | URL نهایی را با فایل روی دیسک و در روش CSS با مسیر نسبی همان CSS تطبیق بده |
| درخواست 200 است ولی فونت decode نمی‌شود | Preview/Response را ببین؛ پاسخ ممکن است HTML یا فایل خراب باشد؛ پسوند و format واقعی را بررسی کن |
| نام Computed درست است ولی ظاهر فرق ندارد | `Rendered Fonts` متن، پوشش حروف، نسخهٔ فایل و قوانین روی خود عنصر را بررسی کن |
| فقط عنوان یا دکمه فونت قبلی دارد | قانون `font-family` یا shorthand به نام `font` روی همان عنصر ممکن است بر ارث‌بری غلبه کند |
| وزن‌ها شبیه هم‌اند | نوع واقعی فایل، بازهٔ `wght`، فایل‌های وزن ثابت و مقدار computedِ `font-weight` را بررسی کن |
| فونت در همهٔ زبان‌ها دیده می‌شود | محل CSS در پوشهٔ عمومی، enqueue دستی، `@import` و Initiator درخواست را بررسی کن |
| بعد از تعویض فایل هنوز نسخهٔ قبلی است | کش مرورگر و در صورت وجود کش صفحه/CDN را بررسی کن؛ برای نسخهٔ جدید نام فایل تازه بگذار و path را هماهنگ تغییر بده |
| اخطار preload استفاده‌نشده می‌بینی | family مصرفی، زبان، وزن و یکسان‌بودن URL preload و face را بررسی کن؛ preload را برای فایل غیرضروری خاموش کن |
| آیکن‌ها تبدیل به مربع شده‌اند | قانون سراسری یا `!important` ممکن است فونت آیکن را بازنویسی کرده باشد |

جزئیات کش در پیاده‌سازی فعلی: `cn_asset()` مقدار `filemtime` را هم برمی‌گرداند
و stylesheet خارجی با آن version می‌گیرد؛ اما `src` فونت تولیدشده و URL
preload از `$asset['url']` بدون اضافه‌کردن این نسخه استفاده می‌کنند. پس تغییر
بایت‌های فونت با نام ثابت، به‌خودی‌خود URL دانلود جدیدی تولید نمی‌کند. پارامتر
`?v=2` را به `path` فایل اضافه نکن؛ این مقدار برای بررسی فایل روی دیسک هم
استفاده می‌شود. نام فایل تازه و path هماهنگ، روش روشن‌تری است.

## ۱۴. بازگشت از تمرین و معیار پایان

برای بازگشت از مثال اصلی، همان filter اضافه‌شده را حذف کن؛ اگر از قبل filter
داشتی و آن را ویرایش کردی، نسخهٔ قبلی‌اش را برگردان. با درخواست تازه و رفع
کش مرتبط، تنظیم پایهٔ فارسی دوباره Dana خواهد بود. صرف باقی‌ماندن فایل فونت
در `assets/fonts` باعث دانلود آن نمی‌شود. markup و استایل‌های آزمایشی را هم
پس از بررسی بردار و اگر SCSS را تغییر داده‌ای، CSS متناظر را دوباره بساز.

وقتی این موارد برقرار باشند، سناریو کامل شده است:

1. فایل واقعی در مسیر درست قرار دارد و کد PHP خطای نحوی ندارد.
2. نام خانواده، نوع فایل، وزن و زبان در تنظیم هماهنگ‌اند.
3. HTML صفحهٔ فارسی تعریف درست و preload مورد انتظار را دارد.
4. Network دانلود موفق و `Rendered Fonts` استفاده از فایل درست را نشان می‌دهد.
5. وزن‌های مورد استفاده، عنوان‌ها، ورودی‌ها و رقم‌ها بررسی شده‌اند.
6. صفحهٔ انگلیسی منابع فارسی را از این تنظیم دریافت نمی‌کند.

برای مرور سریع تنظیم‌ها به [FONTS.fa.md](./FONTS.fa.md) و برای شرح جزئیات
توابع داخلی به [مرجع inc/fonts.php](./inc/fonts.fa.md) مراجعه کن.
