# VoiceWeb Auth

افزونهٔ مستقل ورود و ثبت‌نام موبایلی برای وردپرس، با اتصال به حساب‌های ووکامرس.

کاربر جدید ابتدا شمارهٔ موبایل خود را تأیید می‌کند و سپس نام کاربری و رمز
می‌سازد. ورودهای بعدی به‌صورت پیش‌فرض پیامکی‌اند؛ ورود با نام کاربری، ایمیل یا
موبایل تأییدشده و رمز ثابت نیز در همان رابط موجود است.

## نصب و استفاده

پوشهٔ `voiceweb-auth` را داخل `wp-content/plugins` قرار دهید و افزونه را فعال کنید.
در **تنظیمات ← ورود ویس وب** اطلاعات سرویس پیامک را وارد کنید. رمز سرویس با
کلید مشتق‌شده از salt وردپرس رمزگذاری می‌شود و در HTML یا JavaScript قرار نمی‌گیرد.
تغییر saltهای وردپرس نیاز به ثبت دوبارهٔ رمز سرویس دارد.

اگر می‌خواهید ماژول را به‌جای فعال‌کردن افزونه از `functions.php` وارد کنید:

```php
require_once WP_CONTENT_DIR . '/plugins/voiceweb-auth/voiceweb-auth.php';
```

ماژول را می‌توان با همین ساختار داخل پوشه‌ای از قالب هم گذاشت و فایل اصلی را
با `require_once` بارگذاری کرد. URL فایل‌های آن از مسیر `wp-content` محاسبه می‌شود.
برای محل‌های خارج از `wp-content` از فیلتر `voiceweb_auth_asset_url` استفاده کنید.

برای افزودن دکمه به هر قالب:

```php
echo voiceweb_auth_account_link( array( 'class' => 'my-account-button' ) );
```

برای قرار دادن فرم کامل یا دکمه در یک برگه:

```text
[voiceweb_auth]
[voiceweb_auth_button]
```

لینک‌های معمول `wp-login.php` در فرانت‌اند نیز خودکار به پنجرهٔ ورود وصل می‌شوند.
برای مستثناکردن یک لینک، `data-vwa-ignore` را روی آن قرار دهید.

## تجربهٔ کاربر

- فرم ورود پیامکی در برگهٔ حساب من ووکامرس جایگزین فرم مهمان می‌شود.
- در دسکتاپ، دکمهٔ حساب در هدر VoiceWeb پنجرهٔ ورود را باز می‌کند.
- در موبایل، نوار ثابت خانه، فروشگاه و ورود/حساب همراه با safe area نمایش داده می‌شود.
- تکمیل خودکار کد با `autocomplete="one-time-code"` و WebOTP، و رمزها با
  `autocomplete="username"`، `current-password` و `new-password` پشتیبانی می‌شوند.
- تکمیل خودکار پیامک به HTTPS، مرورگر پشتیبان و تأیید کاربر وابسته است؛ ورود
  دستی و چسباندن کد همواره ممکن است. قالب SMS شامل خط آخر `@domain #code` است.
- دکمهٔ ارسال دوباره، ویرایش موبایل، نمایش رمز، خطاهای خوانا، بازگشت، حفظ فوکوس،
  کنترل با صفحه‌کلید و نمایش مناسب هنگام بازشدن کیبورد موبایل موجودند.

حساب موبایلی بدون ایمیل ساختگی ایجاد می‌شود. ایمیل واقعی مشتری در خرید یا
ویرایش حساب ووکامرس دریافت می‌شود. مشتریانی که هنوز ایمیل ندارند برای ورود از
موبایل یا نام کاربری استفاده می‌کنند؛ ایمیل‌های فروشگاه پس از ثبت ایمیل واقعی
به همان نشانی ارسال می‌شوند.

حساب قدیمی با شمارهٔ صورتحساب به‌صورت خودکار به ورود پیامکی متصل نمی‌شود. برای
اتصال، مشتری شماره را با کد تأیید می‌کند، در مرحلهٔ ساخت حساب گزینهٔ «قبلاً حساب
دارید؟» را می‌زند و با رمز صحیح حساب قبلی وارد می‌شود.

## رفتار امنیتی

کدها شش‌رقمی، پیش‌فرض دارای اعتبار پنج دقیقه، متصل به مرورگر و یک‌بارمصرف‌اند.
فقط HMAC کد و توکن در دیتابیس ذخیره می‌شود. تکمیل ثبت‌نام نیاز به اثبات تأییدشدهٔ
همان مرورگر دارد که ده دقیقه معتبر است. پس از پنج کد غلط، درخواست کد جدید لازم است.

درخواست‌ها Origin و توکن CSRF مختص cookie خصوصی مرورگر را بررسی می‌کنند. محدودیت
ارسال برای موبایل و IP، محدودیت تلاش رمز و قفل اتمی ارسال/ثبت‌نام اعمال می‌شود.
IPهای اعلام‌شده در header پراکسی به‌صورت پیش‌فرض مورد اعتماد نیستند.

ورود پیامکی پیش‌فرض فقط برای `customer` و `subscriber` مجاز است؛ حساب‌های مدیریتی
از رمز و مسیر ورود معمول وردپرس استفاده می‌کنند. رمز کاربران با سازوکار استاندارد
وردپرس ذخیره می‌شود. پاسخ‌ها cache نمی‌شوند و پیامک، کد و اطلاعات سرویس در لاگ
افزونه قرار نمی‌گیرند.

غیرفعال‌کردن افزونه کاربران، اطلاعات مشتری و اتصال موبایل‌های تأییدشده را حذف
نمی‌کند. cron روزانه فقط درخواست‌ها و محدودیت‌های منقضی‌شده را پاک می‌کند.

## توسعه

ماژول‌ها در `includes` به بخش‌های مستقل Plugin، Auth، Database، Security، SMS،
Settings، UI و Text تقسیم شده‌اند. فایل‌های CSS و JavaScript مستقل از Bootstrap،
jQuery، ACF و قالب VoiceWeb هستند.

فیلترهای توسعه:

| فیلتر | کاربرد |
| --- | --- |
| `voiceweb_auth_sms_gateway` | تزریق یک کلاس مشتق‌شده از `VoiceWeb\Auth\SMS` با متدهای `configured()` و `send()` |
| `voiceweb_auth_asset_url` | تعیین نشانی فایل‌ها برای نصب‌های سفارشی |
| `voiceweb_auth_account_url` | نشانی حساب مشتری |
| `voiceweb_auth_registration_enabled` | سیاست مجازبودن ثبت‌نام |
| `voiceweb_auth_registration_errors` | اعتبارسنجی تکمیلی ثبت‌نام؛ خروجی `WP_Error` |
| `voiceweb_auth_allow_sms_login` | سیاست ورود پیامکی نقش‌ها |
| `voiceweb_auth_client_ip` | تعیین IP از یک پراکسی مورد اعتماد |

رویدادهای `voiceweb_auth_registered` در PHP و `voiceweb:authenticated` در مرورگر
برای اتصال قابلیت‌های دیگر موجودند. endpointها زیر `voiceweb-auth/v1` با POST
ثبت می‌شوند: `session`، `request-code`، `verify-code`، `register` و `password-login`.

منابع سازگاری:
[مستندات ارسال پیامک مهر افراز](https://mehrafraz.com/fullrest/Help/Api/POST-api-Send)،
[مستندات WebOTP و قالب پیامک](https://developer.chrome.com/docs/identity/web-apis/web-otp).

## بررسی‌ها

برای بررسی جریان واقعی وردپرس و دیتابیس، از ریشهٔ نصب وردپرس اجرا کنید:

```sh
php wp-content/plugins/voiceweb-auth/tests/regression.php
php wp-content/plugins/voiceweb-auth/tests/module-bootstrap.php
```

در نصب‌های محلی با پورت اختصاصی MySQL، گزینهٔ `-d mysqli.default_port=PORT` را به PHP بدهید.
این بررسی از درگاه پیامک شبیه‌سازی‌شده و حساب‌های موقت با پیشوند تصادفی استفاده می‌کند و در پایان
فقط داده‌های خودش را پاک می‌کند. بهتر است آن را روی نسخهٔ توسعه اجرا کنید.

برای بررسی رابط دسکتاپ، موبایل و حساب من، با Playwright نصب‌شده اجرا کنید:

```sh
VOICEWEB_AUTH_SITE=https://example.test node wp-content/plugins/voiceweb-auth/tests/browser-smoke.cjs
```

در PowerShell ابتدا `$env:VOICEWEB_AUTH_SITE = 'https://example.test'` را تنظیم کنید.
متغیرهای اختیاری `VOICEWEB_PLAYWRIGHT_PATH`، `VOICEWEB_BROWSER_EXECUTABLE` و
`VOICEWEB_AUTH_SCREENSHOTS` به‌ترتیب مسیر Playwright، مرورگر و پوشهٔ تصاویر بررسی را تعیین می‌کنند.
در این بررسی درخواست‌های ورود و پیامک شبیه‌سازی می‌شوند؛ پیامک واقعی و حساب جدید ایجاد نمی‌شود.
